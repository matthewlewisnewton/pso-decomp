# Panarms native emission evidence

The native body and PanBARA half retain their original code/data ranges while the old tail is folded into its owning body. Their compiler-generated initializers and member-function-pointer constants come from C++ action tables, not handwritten tables or binary patches. The half uses supported deferred emission, small-data placement and source-private header definitions to retain the original initializer/helper ordering and constant pool. This bounded arrangement does not establish original filenames or source order.

The compiler emits each native member-function-pointer constant as a separate local 12-byte object. The body has 28 constants at 8049500C–8049515C; the half has 34 at 804955C4–8049575C. Compiled allocated data sections and relocation sequences match the original. Historical metadata grouped each complete sequence into one symbol. That grouping made objdiff's synthetic R_PPC_NONE references associate original initializer loads with the entire sequence while compiled loads referenced individual constants, despite identical instructions. The metadata now uses local address placeholders at the observed 12-byte boundaries. No bytes, linker ownership or checker behavior change, and no semantic names are inferred from these compiler labels. Actual ADDR32 relocation positions and targets, complete data layout, source-linked address coverage and the final DOL must all still match.

The current canonical init action at 800DFB00 takes s16, as in the existing symbol and its change_action call. NPC descriptors use the shared NpcAnimationBinding and typed registry, with copy initialization rather than an invented four-word duplicate type. The descriptor's final two bytes remain padding; no field is invented for them. Complete emitted instructions/data/relocations are checked rather than assuming copy behavior from layout alone.

The previously linked collision unit retains inherited provisional overlays and helper signatures. Its implementation is retained from the certified core; the added constructor declaration only exposes the existing native entry to the recovered body. This change does not claim complete collision-interface or placeholder semantic recovery.

The Re4Bit event handler previously borrowed the unrelated Panarms layout for its own flags at3CC and timer at408. Recovering the Panarms header exposed that obsolete cast. The caller now uses its actual Re4Bit class, with the existing padding split to expose the already-used flag word. Offset/size assertions and complete object comparison preserve the native layout and bytes; no shared base interface changes.
