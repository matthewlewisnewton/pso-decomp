## Compiler comparisons

The initial C probe reproduces the unsigned conversion and scale store.
Defining the scalar before its C++ consumer emits two copies, an eight-byte
`.sdata2` section where the original scalar occupies four bytes. The
literal-pool approach documented in
[loading particle distance](now-loading-constant-pool.md) and
[laser-light constants](laser-light-constant-pool.md) emits exactly four
bytes and preserves the store instructions. No compiler override or
section annotation is needed. The original and compiled consumer census
in `localize_split_globals.py` finds no other reference requiring
`lbl_805DD138` to remain global, so it becomes `scope:local`.

The subtraction helper retains its `u32` input and ordinary float cast.
GC/2.6 emits its original eight-byte unsigned conversion bias and the
original sequence of loads, stores and floating-point subtractions.

Replacing the submenu aliases with calls through the existing
`TWindowMainMenu` declarations changes register allocation. Direct receiver
casts, a local receiver with a saved entry, and explicit receiver ABI
aliases also fail instruction matching. This change retains the existing
provisional boundary and the signed 16-bit entry narrowing. The receiver
and return declarations need joint recovery with the surrounding menu
units; their current names and declarations are not independent proof of
the original interface. The offset-based scale accesses likewise remain
bounded rather than assuming the incomplete shared header's field layout.
