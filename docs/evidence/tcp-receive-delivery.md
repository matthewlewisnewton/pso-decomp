# TCP receive delivery at 0x8041F204

This function consumes packet fragments for a pending user read, delivers its callback, and copies the remaining bytes into the receive ring. A callback can register another read. The caller in TCP input passes the active control block and the combined header length as a 16-bit skip. The two buffer descriptors used by the function are each eight bytes.

The local GPOE8P disc also contains two executables with the same AVE-TCP routine. In `iwanaga.dol` it begins at `0x80151CC4`. All 282 instruction words correspond to the retail routine after resolving calls and addresses. The independently compiled `iwanagaD.dol` routine begins at `0x8016C080`. At `0x8016C1AC` it compares the room in the pending read with the remainder of the fragment. The two arms recompute the selected byte count. This gives the source a direct unsigned comparison and one copy length. After exhausting the fragments, the debug build tests the pending read after its completion callback. The switch cases for states 0, 5, 7, 8 and 10 report `-7`. Its exits converge at `0x8016C550`. The fork uses the upstream receive flow and these independent observations. [Upstream source](https://github.com/zeroz41/pso-decomp/blob/256e5a7d353d47f899c22c0ec148a75064d96079/src/pso/network/SocketProtocolRuntime.c)

The callback receives a public socket handle. UDP input passes its socket-table index to `0x80421F10`, which sets the UDP tag in the callback record. The UDP close and send APIs check the same tag. TCP receive checks for a zero protocol field under mask `0xC00`. In the debug executable, UDP sets `0x400` for the callback at `0x8016F038` and for the socket returned to the caller at `0x8016F208`. TCP completion indexes the table using a signed halfword at `0x8016EA4C` and passes the signed handle to its callback at `0x8016EA84`. TCP and UDP share the public-handle encoding in C++. These observations establish the values and uses of the tags. The original spelling is unknown.

The partial-read completion path makes one decision after its callback. A callback can install another user read. The routine clears that new read and reports `-7` in states 0, 5, 7, 8 and 10. All other states leave the new read pending. A callback that installs another read during the `-7` notification leaves that read pending as well.

The direct `if (control->rcv_user.kind != 0)` produces 1,120 bytes with GC/1.2.5n. Retail uses 1,128 bytes. The game and both same-disc browser builds branch forward over the closed-state switch to test the pending flag, then branch back to the switch when the flag is set. The compiler puts the test before the switch for the direct conditional. A comparison of the two PowerPC instruction graphs followed both outcomes at each conditional, resolved both eleven-entry jump tables, and checked external call targets. After following unconditional branches, all 281 visited instruction pairs agreed. The compiler assigns different addresses to the switch targets. Objdiff scores the function at 97.66%.

Other tested source forms included an inverted guard, a shared closed-state handler, a state predicate, early returns, and an outer loop that can process additional user reads. None reproduced the retail layout. The direct conditional also remained nonmatching across 20 installed GameCube compiler versions. Host tests under address, undefined-behavior and bounds sanitizers exercised skip and FIFO wrap plus 104 combinations of TCP state, exact or partial completion, and callback re-registration.
