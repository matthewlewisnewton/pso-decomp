This integrates main `f8a71fae8a52f0bde1b956af4519061fe306cb30` through focused
head `be9e024f26698be013626a8591bd25150228825f`, following continuation
`9cefcb0dd3079a9b3766467365927dc7d16e4260`. The published stack/history is

## Combined source and retained qualifications

The 0x78-byte class remains Base-derived. Its native word-valued constructor,
260-byte code and ordinary-new producer in the unchanged 584-byte CtrlPlayer
unit remain intact. The actual native task and renderer retain Base fields and
methods. Main's consolidated definition order, deferred profile and render-first
key declaration are retained; inherited virtual slot positions do not change.
This is accepted reproduction context, not proof of retail source order or a
license to rearrange other units until they match. No Word profile or ordering
diagnostic is activated.

The five separate UV arrays, icon's `int` group and `u16` slot, count-label
contract and real TItem amount call come from main. The existing four-byte free
tag exports are retained instead of casting tag storage to a whole window.
The three-record array-runtime protocol and the original loop that resets the
first tag three times stay unchanged. The deleting boundary still uses its raw
C ABI and explicit Base cleanup in this integration; native destruction is not
claimed here.

The prior 332-byte serialized record schema and 20-byte WindowLayoutDescriptor
are ported into the consolidated source. All size/offset assertions, signed
number value and `GinjaTextureList**` field remain. Each sprite record points to
the address of shared texture-list pointer storage, preserving the established
indirection. The old modified HelpItem fragment is deleted only after its source
work is carried into the new owner; the adjacent Palette light fragment is folded too.

The first combined build caught upstream's flat `HelpItem::m_8` reference, which
does not exist on the recovered Base-derived HelpItem. The continuation's already
qualified raw entry-float access at +8 is retained. This is an entry view, not a
new TObject/Base field. No field, padding or scheduling variant was introduced.

The external legacy icon declarations retain their existing word/short, pointer
and ignored-result views; they are not a globally portable shared contract.
Array callbacks, unchecked icon indices, first-tag reset asymmetry, the light
helper's arity and other entry/helper ownership qualifications remain. Exact
source linkage does not clear those source-quality holds.
