# Native Nest continuation

This is a prospective unit-only reapplication of the native Nest implementation from immutable `305dc117506d1b40ce6645588d84458ad252b7ce` onto fork base `623d9415a5edb3e27c686135385dcf98b5fa36bc`, then normally merged with certified foundation `a166aa963a4afefc9d94608aeb4411a2b26dbf33`. It is not validated against this base yet. Required shared interfaces must be stacked before a matching build, integrated review or ready claim; no shims or shared definitions are added here.

The unit uses native construction, destruction, init, state dispatch and task update with compiler-generated virtual tables. Its private CarryFly has vector and state fields. Only the required Fly factory, Nest resource accessor and two removal notifications change in the sibling source. The empty shadow override at `0x800B4820` belongs to Nest and moves from the Wolf source with its four-byte text range. Other current fork source and shared definitions are retained.

Private resource descriptors, filename strings, motion tables, scalar pools and stat handles are defined in source. Symbol/config changes are selected by the verified Nest address ranges and bounded Fly factory at `0x800B225C`; other units' names and emission settings stay as on the base. The old completed checkpoint has 43 exact source-linked functions, 9348 code bytes and 1688 data bytes, but those results do not certify this new reapplication.

Definitions are reversed under supported deferred code generation, with readonly strings, to reproduce the constructor reference pool and compiler virtual-table/jump-table/CarryFly-table ordering. This organization had explicit human approval and is supported by the current contribution policy. Bounded independent compiler research found no tested supported ascending-order alternative; it does not prove original source order or universal impossibility. No handwritten table, assembly, fabricated reference or binary postprocessing is used.

Prior object comparisons record identical allocated bytes, sizes and normalized relocations, with the known `.sdata2` extracted-target/compiler section flags distinction (2/3). Compiler flags agree with pristine source objects; the original DOL hash was preserved. Four symbol-free zero data-padding bytes leave report coverage. Both distinctions must remain explicit in the new validation.

Missing contracts on the exact base include the atomic DD descendant-slot correction (root float slot must be removed together with the real Nest/Joint/Mine first slots), receiver-based scaled random, full-register phase predicate, provisional neutral hooks, typed node callbacks and the reviewed texture/particle/sound interfaces. The existing generic draw entry and dead-spot input interfaces are already compatible on this base. Shared API spelling, including the canonical model-node type, must follow the owner's final immutable projection rather than a local substitute.

The neutral hooks, sound retained-position lifetime, heterogeneous texture/model producers, callback/cache creator and external manual initializer boundaries remain bounded. The three existing receiverless render helper calls have original-call ABI evidence; that does not prove their original C++ source spelling or globally valid returns. A successful future bounded integration is not full recovery of these surrounding subsystems.

The foundation is retained in full. Its typed motion setters and free demo-mode predicate are consumed directly; no obsolete `TUnk_80494938` header or generic definitions are restored. `RenderFadeState` remains the correct separate camera-fade type here and is not replaced with `MaterialOpacityFade`. The pending shared state/group/node/capture/collision draft layers are not treated as certified prerequisites. No duplicate clean baseline build is required for source-identical foundation evidence.
