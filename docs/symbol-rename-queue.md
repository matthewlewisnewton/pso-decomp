# Reviewed symbol signature renames in source maintenance

The source-maintenance policy may admit a narrowly reviewed rename in `config/GPOE8P/psov3/symbols.txt` alongside permitted C/C++ source changes. All normal source-maintenance acceptance gates remain mandatory, including both original DOLs, unfiltered raw coverage/exact/source-link preservation and identical actual ordered linker inputs. Recovery and tools-only maintenance are unchanged. No other configuration file or build/check tool becomes eligible.

The selected batch must include an operator-provided `symbol_rename_review` object with an absolute external review `path` and its `sha256`. The independently authored review JSON requires `version: 1`, `verdict: "pass"`, `independent: true`, a nonempty `reviewer`, the exact batch `target`, the ordered selected `heads`, `path` equal to the symbols file, `before_sha256` and `after_sha256` of the complete files, and an ordered `renames` list. Each rename specifies `old`, `new`, `section`, `address` and `size`. The review must substantively assess the exact names and source changes; computing a hash is not review. Normal exact-head PR review and hosted checks remain separate requirements.

The trusted CLI checks the target and merged candidate blobs and independently parses every record. It reads raw Git blobs, rejects all controls except literal LF, and splits records only at literal LF. It accepts only changes in the name field at the same line, with identical section, address, size, type, flags, whitespace and all remaining metadata. Both renamed names must be globally unique in their respective files, the new name must not already exist, and the old name must disappear. Existing unrelated duplicate local names are tolerated. The currently supported subset requires a recognizable length-prefixed class-method mangling with the same method and class owner and a changed function signature using the supported primitive type codes. Unsupported names fail closed and need a separately reviewed extension. Added, deleted, reordered, malformed or otherwise changed records fail; unrelated config changes remain forbidden. The review is required exactly when the symbols file changes and is rechecked before publication.

For the reviewed movement example, the permitted metadata delta changes `set_flag2__12TObjEneReconFv` to `set_flag2__12TObjEneReconFfff` at `.text:0x8031DDDC`, size `0x50`. A review must bind the actual current target, ordered heads and complete file hashes; this example is not an approval or reusable review record.

This source proposal does not deploy a queue. Obtain independent review of the exact CLI and tests, install and pin trusted code only during a coordinated idle transition, and run a freshly selected pilot with independently reviewed current-main candidate graphs, immutable tools and originals, and the normal live checks and CAS. No candidate code may select or supply the trusted review or validator. Original reports, private review paths and game assets remain local.
